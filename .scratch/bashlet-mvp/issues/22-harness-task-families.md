# 22: 建立三类任务及独立开发清单

**What to build:** 将短程序编写、现有代码修改、工作区信息利用三类简单任务接入已有实验流程，得到有稳定来源、任务家族划分和可执行评分的训练候选池与开发清单。

**Blocked by:** None (can start immediately)。复用已交付的 Task、沙箱和两类评分器。

**Status:** ready-for-agent

- [x] 组合已有编程题与自编小型工作区任务，覆盖按需求创建短实现、读取并修改或修复现有代码、依据工作区实际文件内容完成任务三类行为。难度面向原始模型已有能力，不依赖新增算法知识或更大的模型。
- [x] 为每项任务记录来源、版本、任务家族、任务类型、split 和内容身份；同题改名、改写、错误版本、环境变体及其轨迹均保留同一家族，不能跨训练与开发划分。保留已有 MBPP 来源及 split 校验，增加自编任务的明确准入规则，不把未知来源一律当作可信数据。
- [x] 冻结 30 项 Harness 开发任务，每类 10 项，并登记已有 37 道已验证 MBPP 开发题作为独立编程检查清单。两种检查用途分开；如有题目重叠，明确记录且不相加为独立样本。最终测试集不参与这轮构造、筛选和调参。
- [x] 训练候选池覆盖三类任务，供后续筛选最多 60 条有益示范，初始目标各约 20 条；不为了凑数量降低任务或示范质量。冻结家族归属后，任何补充任务也经过相同隔离检查。
- [x] 至少预留一种必须利用真实工作区信息或执行反馈的开发场景，关键内容不能全部写在初始需求中或由题名猜出。环境变体与反馈起点有稳定身份，属于原任务家族；不能把多个变体当成额外独立题目扩大分母。
- [x] 每项任务有可执行的正确性判据，参考行为经过真实执行验证，并用至少一个有针对性的错误实现检查评分能发现错误。反馈材料与隐藏评分材料分离，工作区内容、指令与评分要求一致；学生接触不到参考解或隐藏答案。
- [x] 收敛当前任务清单读取和来源校验中对 MBPP 的绑定，使同一实验入口能够读取多来源任务；不增加任务专用 Harness 或要求所有任务使用相同文件名、写文件命令或交互步骤。
- [x] 三类任务各有一个最小端到端例子，经已有实验入口或 CLI 执行并独立评分；同时验证错误提交被拒绝、家族跨 split 被拒绝、隐藏材料不进入观察。数据清单及验证产物可复查，测试替身结果不标为模型基线。
