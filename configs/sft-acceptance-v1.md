# 双轨 SFT 验收 v1

`sft-acceptance-v1.json` 固定任务、三个 seed 和比较规则。新训练前先运行原始模型的 `evaluate-acceptance`，保存 `acceptance.json` 中的冻结内容和 SHA-256；本轮后续训练沿用这份内容。已训练的旧快照可用于校准和排错，不能将旧评测改名为新基线。协议、环境、编码、服务栈、精度、相应检查预算、HTTP 超时／重试／等待及采样条件改变时，需要新的匹配基线。旧记录遗漏的 HTTP 默认值从已保存的构造配置按同一客户端定义恢复，原始文件和哈希保持不变；相同请求策略的完成 seed 仍可复用。

| 检查 | 固定家族分母 | 执行方式 |
| --- | ---: | --- |
| Harness | 30，三类各 10 | 共用 `run_experiment`、真实 bash 观察、明确提交和独立评分 |
| 编程 | 37 | 一次直接生成 Python；宿主写入答案后独立评分 |
| 许可证政策变体 | 1，已属于 Harness 家族 | 额外的真实环境检查，不加入 30 项分母 |

两个主检查共用 10 个 MBPP 家族，分别报告，不把 30 与 37 相加。seed 固定为 `4, 17, 29`；跨 seed 和环境变体继承家族身份，不增加独立任务数。最终测试数据不参与此流程。

## 提示、提取和预算

Harness 条件来自版本化 YAML。当前本地条件叠加 `local-base.yaml` 和 `acceptance-local-v1.yaml`；候选再叠加相应快照配置。初筛只跑 seed 4，确认扩展到三个 seed，总计使用三份结果。`--resume` 校验冻结内容、快照、条件和已完成记录的哈希，复用完成的结果。未完成尝试保留缺口，不靠重复尝试增加证据。

编程检查使用 JSON 中的 `coding` 提示，保留 MBPP 原需求及函数签名，移除转换器附加的反馈测试／提交说明。学生看不到参考代码、反馈测试文件或评分输入。编码使用同一真实 tokenizer 和模板，thinking 沿用模型配置；原始 token、logprob 和停止原因保留在运行记录。

编程回答必须只有一个非空 `python` 围栏块，围栏外只能有空白。提取规则不补导入、不修语法、不修答案；空块、多块、其他语言、正文夹杂解释或截断回答均失败。宿主只写入函数评分器声明的 Python 模块，然后调用同一个独立评分路径。没有 bash 协议，也没有第二次模型调用或工具反馈。每题固定最多 1024 token、120 秒；temperature=1、top_p=1。候选与基线一致。

## 决策

每个候选均保留 `qualified`（合格）、`ineligible`（不合格）或 `insufficient`（证据不足），以及原因、逐类差值、证据缺口、快照及 sampler／训练状态身份。

- 缺少确认 seed、基础设施错误、身份或文件哈希错误、条件不同：证据不足。初筛可标记有希望，但不合格。基线和候选的所有记录都必须属于同一证据类型。
- 回退按家族汇总三个配对 seed 的成功差值；用汇总差值的正负家族数做单侧 exact sign test。至少两个 seed 的通过数减少且家族回退 p≤0.05，记为确认回退。独立编程或任一 Harness 类别确认回退即不合格，其他类别收益不能抵消。
- 某类别在至少两个 seed 减少，但家族证据未达到上述规则：证据不足。编程检查任一确认 seed 的通过数减少，也不宣称保持。
- 完整确认中总体 Harness 成功没有增加：不合格。格式改善、测试／读取／修复计数、耗时或 loss 不能代替任务收益。
- 合格还要求编程在三个 seed 中均保持或增加，以及至少两个不同工作区家族在至少两个 seed 中成功改善、没有该家族的反向差值，并通过观察与实现依赖审阅。固定环境变体出现负向差值时暂不接纳工作区收益结论。
- 合格候选按三 seed 的 Harness 总成功数选优；同分选择 optimizer step 更早的快照。

这是小样本开发验收规则。合格记录表示固定任务上的可复核收益，不宣称普遍能力提升或统计显著的非劣。失败恢复集合仍按模型分别记录，仅作描述；本版采用工作区场景，不作受控失败恢复提升的声明。

## 工作区收益审阅

审阅者同时检查候选与基线的任务成绩及实际轨迹。审阅 JSON 使用 `workspace-benefit-review-v1`，绑定两份 `acceptance.json` 的 SHA-256。每项记录 `task_id`、`seed`、`observation_step`、`implementation_step`、`observed_paths`、`reason` 和 `author`。步编号从 0 开始。`reason` 解释实现如何依赖真实状态，不能只写“用了 cat”或“步骤更少”。

选择器核对成功来自独立评分，真实可见观察包含所列初始文件内容且文件没有被改写，并核对随后实现文件确有变化。审阅项只有对应改善的 seed 才计入收益。文件哈希和观察来源可追溯；代码依赖的语义仍是明确的审阅判断，不由命令频次自动推断。

`select-sft` 只接收双轨结果，旧单轨评测不能建立新的学生／教师起点。没有合格候选时，`selection.json` 的三个起点字段为 null。测试替身可用 `--evidence-kind test-double` 演练决策；即使模拟合格，也只写 `simulation_selected_snapshot`，不写生产学生／教师起点。旧 selection 文件保留，新选优可指定新的 `--output-dir`。

## 运行和监控

用 `evaluate-acceptance --stage screening` 初筛；有希望时，在相同服务下用 `--stage confirmation --resume <acceptance.json>` 扩展候选及基线。先切换并验证服务身份，再运行对应配置。数据与轨迹位于 `runs/`，测试替身与真实运行分别标记。

每个 track／seed 复用既有 W&B 指标、配置允许字段和本地日志。当前 `acceptance-monitoring.yaml` 使用 offline，生成可同步的缓存；上传只包含指标、脱敏配置和快照引用。完整轨迹、代码、权重和隐藏评分材料保留本地。在线同步需要使用已授权的账号目标和既有 `bashlet monitor sync` 入口。
