# 任务 27：原始模型 v3/v4 配对小试

2026-10-04，18/18 次预定尝试已完成。v4 改善了这九个训练家族上的
行动格式与提交行为，但工作区类型仍无合格模型示范。此结果支持后续
采集优先试用 v4；它不是独立能力评测，也没有批准后续阶段预算。

| 协议 | 有效行动 | 格式错误 | 虚构观察回复 | 提交／评分通过 | 质量候选 | 可加载示范 |

## 冻结条件与来源

[preflight.json](preflight.json) 在采样前保存已解析条件、代码及配置哈希。
[selection.json](selection.json) 与 [tasks/manifest.json](tasks/manifest.json)
冻结每类前三个已验证训练家族，选择依据是原 v1 清单顺序。没有按旧模型
结果选择任务，没有新增开发或最终测试家族。九个 Task 的完整初始文件、
来源、划分、参考实现、私有评分、反馈起点和环境变体均单独保存。

实际模型为原始 `Qwen/Qwen3.5-4B`，revision
`851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，vLLM 0.17.1、BF16、
thinking=false。原始权重、tokenizer 与模板哈希由既有 LocalSnapshot
校验；服务 root、实际加载器、无 LoRA 配置、tokenizer 编码比对和逐 token
logprob 探针见 [capability-probe.json](capability-probe.json) 与
[api-base.json](api-base.json)。没有把旧 SFT 服务当成原始模型。

两组只改变协议名称和系统提示。temperature=1、top_p=1、seed=4，单次
最多 1024 token；每回合最多 10 步、8192 生成 token、300 秒，连续三次
格式错误停止。HTTP timeout=120 秒、max_retries=0。完整历史只追加。
两组服务窗口及冻结历史上限均为 16384 token，最大实际历史为 1640 token。
没有上下文耗尽、生成 token 耗尽或时间耗尽；v4 四次耗尽的是 10 步上限。

原服务 PID 3767051、GPU engine PID 3768515 保留在 8000 端口，实际模型为
`sft-step12`。新原始模型服务使用 8001 端口、单序列、eager、
gpu-memory-utilization=0.30、language-model-only、generation-config=vllm。
实际推理配置由各回合保存，两协议一致。小试结束后只停止新服务。
[old-service-proof.txt](old-service-proof.txt)、
[old-service-after.json](old-service-after.json) 和 [gpu-after.txt](gpu-after.txt)

## 后续采集建议与已批准边界

本票已批准并执行的是九家族、十八次尝试、两小时本地 GPU 上限和新增
付费 ¥0。正式批量采集、新 LoRA 训练、开发选优、OPSD 和最终测试均未执行。

对任务 28 的建议如下；这些建议尚不是新的已批准决定：

- 协议优先 v4。先用每类三个家族的小批完整链路验证，再扩大到现有
  每类二十个训练家族。保持来源、split、环境、编码、预算及协议版本可追溯。
- 采用已验证的本地原始模型 v4 与冻结参考实现辅助来源。短程序和代码修改
  可先尝试模型采样；工作区覆盖优先使用经真实执行的参考辅助构造或真实
  失败前缀修正。生成机制需要在任务 28 中验证，额外参考信息不进入正常
  学生上下文，隐藏评分不提供给生成端。本票没有验证外部供应商。
- 本地原始模型每家族建议最多两次采样，共最多 120 次；失败记录全部保留。
  未取得干净候选时，最多追加一次明确来源的参考辅助构造。每家族目标一条
  优质示范，第二条仅在增加互补行为时接纳，总量目标为 60–120 条。
- 不把正常读文件或反馈通过当作已经提交。工作区示范必须展示代码如何使用
  实际文件，并通过隐藏 fixture；参考构造也必须经过相同执行、审阅和加载。
- 本地 GPU 建议另设最多两小时的新阶段上限、新增付费默认 ¥0。新阶段开始
  前重新冻结实际边界并核对资金及在途占用，不沿用本票剩余额度或历史 ¥5。
- 达到家族尝试上限、阶段 GPU/费用上限或基础设施中断时停止，保存缺口；
  质量、精确回放或加载不通过时拒绝。正常结束需各类二十个独立家族至少
  一条可加载示范；不足时报告实际覆盖，不通过重复尝试增加独立家族数。

## 代码与验证

读取两个协议的不可变运行及显式回复审阅。它保留未开始的预定分母，检查

超出窗口时保留原历史并报告上下文耗尽，不截断证据。

bash、沙箱或评分。新增 CLI 集成测试使用可控模型边界及真实沙箱，覆盖
中断分母、错绑原回复拒绝和真实输出造成的上下文耗尽；这些测试不作为 v4
有效性的证据。实际验证结果和代码审查另见 `validation.json` 与 `code-review.md`。
